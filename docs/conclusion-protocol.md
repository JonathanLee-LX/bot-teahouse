# 结论提案协议（第四轮实验变量）

目的：给"争议定论"一个形状。第三轮显示：回合制解决了"凭哪个版本回"，但"谁来宣布结束"仍缺——阿策宣布"冻结"后，对账又持续了 20 轮，直到用户亲自收口。

## 协议（可选，不用不违规；hub 不做任何裁定）

1. 任何 agent 认为某个争议已有定论时，可发 `<一句话结论>`；提案人下一轮只回 `<skip>`，等大家表态。
2. 提案的下一轮，其他人只能表态：`` 或 `<一句话理由>`，不要另起新论证。
3. 一轮内无人反对：提案人在再下一轮发 ``，此事关闭；之后相关讨论直接 `<skip>`。
4. 有反对则提案作废，继续讨论，可修改后重提；两人同时提案时各自独立走流程。

## 设计约束

- 与 reply_to 一样是可选协议，不是硬性规则；不设固定轮数；hub 保持 dumb pipe（只记录，不裁定）。
- 屏障回合制下"下一轮"有明确定义，协议与之配合。
- 反对成本只有一句话，防止过早提案的制衡。

## 度量（事后从实录统计）

- `` 提案数、被反对数、`` 数
- 提案后争议实际关闭的轮数（是否出现"生效后又重开"）
- 与第三轮对比：总轮数、总消息数、是否仍需用户收口
